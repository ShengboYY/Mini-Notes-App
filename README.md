# Mini Notes with LLM Summary

A local Anna App take-home implementation. The React iframe stores notes through the Anna storage Host API, invokes a local Python Executa through `anna.tools.invoke`, and receives its summary from reverse JSON-RPC `sampling/createMessage`.

No Anna login, real LLM API key, cloud database, or hosted Anna App is required for the local test paths below.

## Architecture

```text
React iframe
  -> AnnaAppRuntime.connect()
  -> anna.storage.get / anna.storage.set
  -> anna.tools.invoke(tool-dev-notes-summarizer, summarize)
  -> Python Executa invoke
  -> reverse JSON-RPC sampling/createMessage
  -> anna-app mock sampling fixture
  -> summary returned to the UI
```

- `manifest.json` declares the App bundle, UI view, permissions, Host API grants, and the required Executa.
- `src/` contains the engineering frontend source. Vite builds it into `bundle/`, the static iframe payload Anna loads.
- `executas/notes-summarizer/` contains the long-running stdio JSON-RPC Tool.
- Anna storage is the iframe-facing Host API. With `anna-app dev` and no login, it uses the harness's legacy in-memory `runtime_state`.
- Sampling is a reverse RPC from the Executa back to its host; the Tool never holds an LLM API key.
- The binary archive contains a root `manifest.json` plus the platform executable under `bin/`.

The shared local identity is `tool-dev-notes-summarizer` in the App manifest, frontend, `executa.json`, Executa `describe` response, and binary archive manifest.

## Prerequisites

- Node.js 22+
- npm
- Python 3.10+
- `uv`

Install the repository dependencies:

```bash
npm install
npx anna-app doctor
```

The first Anna command may populate the one-time `uvx` runtime cache and create `~/.anna-app/dev.key`. Those messages are expected.

## UI harness: storage and tool wiring

Start the local harness without a real LLM:

```bash
npm run anna:dev
# Equivalent: npx anna-app dev --no-llm
```

Open the dashboard URL printed by the command. In the Mini Notes iframe:

1. Add two notes and confirm they appear in increasing add order.
2. Delete one note and confirm the list updates.
3. Inspect the harness RPC panel for `storage.get` and `storage.set` calls.
4. Click **Summarize** and confirm the panel contains `tools.invoke` for `tool-dev-notes-summarizer`.

In `--no-llm` mode, Summarize is expected to surface an error such as:

```text
[-32603] harness started with --no-llm
```

That error proves the UI reached the Tool route while the harness deliberately disabled its LLM/sampling bridge. It is not the backend sampling test. Notes use the local legacy in-memory runtime state, so refreshing the outer dashboard or restarting `anna-app dev` is not expected to preserve them.

The iframe is not granted `llm.complete` and never calls `anna.llm.complete`.
It only calls `anna.tools.invoke`; the Executa separately negotiates
`llm.sample` before issuing reverse `sampling/createMessage`, as required by
the assignment.

The code evidence for storage is in `src/anna/notesStorage.ts`; there is no `localStorage`, IndexedDB, filesystem, or HTTP persistence path.

## Executa sampling test with an offline fixture

Run the Tool separately with the canned sampling response:

```bash
npm run anna:executa:mock
```

Equivalent command:

```bash
npx anna-app executa dev \
  --dir executas/notes-summarizer \
  --mock-sampling fixtures/sampling.jsonl \
  --invoke summarize \
  --args '{"notes":["Follow up with the client","Fix the login bug"]}'
```

Expected summary:

```text
Follow up with the client and prioritize fixing the login bug.
```

The fixture entry is namespaced as `sampling/createMessage` and only matches a request containing the summarizer prompt. Therefore receiving this text proves the Executa issued reverse sampling; it cannot be produced by the Tool's own rules.

## Bidirectional JSON-RPC protocol test

Run the deterministic protocol driver:

```bash
npm run test:protocol
```

It performs this sequence directly against the Python process, without an
Anna account, network request, or private Python package:

```text
initialize(protocolVersion=2.0)
-> assert client_capabilities.sampling = {}
describe
-> assert raw manifest + host_capabilities = ["llm.sample"]
invoke(summarize, context.invoke_id=protocol-test-invoke)
<- capture sampling/createMessage
-> send a response using the sampling request id
<- assert the final invoke response contains the mock summary
```

This driver is also the complete manual `invoke` test. A one-way `echo ... | python` command cannot finish a sampling invoke because the Tool must receive the reverse response on the same stdin stream.

For quick one-way checks:

```bash
cd executas/notes-summarizer

printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2.0"}}' \
  | uv run python notes_summarizer.py

printf '%s\n' '{"jsonrpc":"2.0","id":2,"method":"describe"}' \
  | uv run python notes_summarizer.py

printf '%s\n' '{"jsonrpc":"2.0","id":3,"method":"health"}' \
  | uv run python notes_summarizer.py
```

The process logs only to stderr. Every stdout line is a flushed JSON-RPC frame, and the main loop continues until stdin reaches EOF.

## Build the current-platform binary archive

The packaging script supports the platforms required by the assignment:

- `darwin-arm64`
- `darwin-x86_64`
- `windows-x86_64`

Build for the current machine:

```bash
npm run package:executa
```

The script detects the platform, runs PyInstaller, stages the binary, writes the archive-root manifest, applies executable permissions, and prints the SHA-256 and size.

On Apple Silicon, for example, it creates:

```text
executas/notes-summarizer/dist-anna/
└── notes-summarizer-darwin-arm64.tar.gz
    ├── manifest.json
    └── bin/
        └── notes-summarizer
```

Inspect and smoke-test it:

```bash
tar tzf executas/notes-summarizer/dist-anna/notes-summarizer-darwin-arm64.tar.gz
python3 scripts/smoke_binary.py \
  --binary executas/notes-summarizer/dist/notes-summarizer
```

Windows produces `notes-summarizer-windows-x86_64.zip` with `bin/notes-summarizer.exe`.

## GitHub Release workflow

`.github/workflows/release.yml` runs when a tag beginning with `v` is pushed. Example:

```bash
git tag v1.0.0
git push origin v1.0.0
```

The matrix uses native runners for PyInstaller:

| Runner | Platform asset |
| --- | --- |
| `macos-14` | `notes-summarizer-darwin-arm64.tar.gz` |
| `macos-15-intel` | `notes-summarizer-darwin-x86_64.tar.gz` |
| `windows-latest` | `notes-summarizer-windows-x86_64.zip` |

Each matrix job runs a JSON-RPC `describe` smoke test against its built executable. The final job downloads all three workflow artifacts and attaches them to one GitHub Release. Workflow artifacts are only intermediate transport and do not replace the Release assets.

## Important implementation details

- Empty notes are rejected in the UI and again in the Executa.
- The persisted document contains both `notes` and `nextOrder`, so deleting a note does not reuse its historical order number.
- Summarize reloads notes through `anna.storage.get` before `anna.tools.invoke`, making the storage-to-tool chain visible in harness logs.
- The Tool advertises sampling during protocol v2 `initialize` and declares `host_capabilities: ["llm.sample"]` in `describe`.
- `metadata.executa_invoke_id` carries the current `invoke_id` on every sampling request.
- One synchronous stdin loop handles Host requests and reverse sampling responses, which keeps the protocol implementation small while preserving the required long-running process behavior.
